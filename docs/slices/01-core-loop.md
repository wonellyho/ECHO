# 기능 1: 사용자가 경험을 기록하고, 목록·상세에서 확인하고, STAR로 변환할 수 있다

이미 구현·배포된 핵심 루프를 사후적으로 문서화한 슬라이스. 새 기능 추가가 아니라
기존 동작을 스펙으로 고정하고, 계산/판단 로직에 테스트를 붙이는 게 목적.

## 완료 조건
(최대 5개까지. 눈으로 확인 가능한 것만)

- [ ] 텍스트를 입력하고 "기록하기"를 누르면 저장 후 AI 구조화를 거쳐 상세 페이지로 이동한다
- [ ] 목록 화면에서 방금 쓴 기록이 보인다
- [ ] 상세 화면에서 구조화된 7개 필드(상황/역할/갈등/행동/결과/감정/감정이유)를 볼 수 있다
- [ ] 상세 화면에서 필드를 수정하고 저장하면 새로고침해도 남아있다
- [ ] "STAR로 변환"을 누르면 결과가 보이고, 새로고침해도 남아있다

## 안 되는 경우
(여기 안 적으면 처리도 안 됩니다)

- 기록 텍스트가 비어있을 때(공백만 입력해도) → "기록하기" 버튼이 비활성화된다 **[계산/판단 → 테스트 대상]**
- 목록에서 태그를 선택하고 키워드를 입력했을 때 → 태그와 키워드 둘 다 만족하는 기록만 보인다 **[계산/판단 → 테스트 대상]**
- 구조화(`/api/structure`) 호출이 실패했을 때 → 에러 문구가 뜨고 다시 시도할 수 있다
- STAR 변환(`/api/star`) 호출이 실패했을 때 → 에러 문구가 뜨고 다시 시도할 수 있다
- 로그인 안 한 상태로 접근 → 로그인 화면으로 보내진다

## 이번에 안 하는 것
(안 적으면 시키지 않은 것까지 만들어 옵니다)

- 인사이트, 자연어 질문 검색, 회원가입, UI 스타일링 — 전부 손대지 않음
- 이미 동작하는 화면의 동작 자체를 바꾸지 않음 (동작은 그대로 두고, 그 동작을 보장하는 테스트만 추가)

## 건드릴 파일
(새로 만들 파일 / 고칠 파일)

- **신규**: `vitest` 설정(`vite.config.ts`에 test 옵션 추가 또는 `vitest.config.ts`), `package.json`에 `test` 스크립트 추가
- **신규**: `src/lib/recordValidation.ts` (제출 가능 여부 판단 로직 추출) + `src/lib/recordValidation.test.ts`
- **신규**: `src/lib/entryFilter.ts` (태그+키워드 필터링 로직 추출) + `src/lib/entryFilter.test.ts`
- **수정**: `src/pages/RecordPage.tsx`, `src/pages/EntriesPage.tsx` — 인라인 로직을 위 함수 호출로 교체 (동작 동일하게 유지)

## 확인 방법
(테스트 + 직접 눌러볼 순서)

1. `npm run test` — 새 테스트 통과 확인
2. `npm run build` — 타입체크/빌드 통과 확인
3. 배포 URL(https://echo-seven-phi-26.vercel.app/)에서: 로그인 → 빈 텍스트로 기록하기 버튼 비활성화 확인 → 기록 작성 → 목록에서 태그 필터+키워드 검색 확인 → 상세에서 수정 저장 확인 → STAR 변환 확인
