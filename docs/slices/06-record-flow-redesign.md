# 기능 6: 기록 화면을 음성/타이핑 두 갈래 + 4단계 플로우로 나눈다

(클로드 디자인 `ECHO Wireframes.dc.html` turn 3 / `3a`~`3d`, 기존 `1c` 대체안)

## 완료 조건
(최대 5개까지. 눈으로 확인 가능한 것만)

- [ ] `/`(기록 화면)에 진입하면 "음성으로 기록" / "타이핑으로 기록" 버튼과 하단 큰 원형 녹화 버튼이 보이고, 녹화 버튼을 눌러도 음성 경로로 들어간다
- [ ] 음성을 선택하면 녹음 화면으로 이동해 실시간 전사 텍스트와, 실제 마이크 입력 볼륨에 따라 움직이는 파형(장식용 고정 애니메이션 아님)이 보이고, 정지 버튼을 누르면 저장 정보 입력 화면으로 넘어간다
- [ ] 타이핑을 선택하면 기존 텍스트 입력 폼(제목·컬렉션 칸은 제외)이 보이고, 완료 시 저장 정보 입력 화면으로 넘어간다
- [ ] 저장 정보 입력 화면에서 프로젝트 제목(추천 목록 포함)과 컬렉션을 고르고 "기록 저장하기"를 누르면 저장 → AI 구조화 → `/entries/:id`로 이동한다
- [ ] 구조화 요청이 실패해도 기록 자체(raw_text)는 이미 저장돼 있고, 저장 정보 화면에서 "다시 시도" 또는 "구조화 없이 저장만 하고 나가기"를 선택할 수 있다

## 안 되는 경우
(여기 안 적으면 처리도 안 됩니다)

- 브라우저가 음성 인식을 지원하지 않거나 마이크 권한이 거부됨 → 진입 화면에서 "음성으로 기록" 비활성 + 안내 문구, "타이핑으로 기록"으로 자연스럽게 유도
- 녹음 중 인식 실패/중단 → 그때까지 받아쓴 텍스트는 유지, "다시 시작" 또는 키보드 아이콘으로 타이핑 전환 가능 (내용 보존)
- 전사/입력 텍스트가 비어 있으면 다음 단계(저장 정보 입력)로 못 넘어감 — 기존 `canSubmitRecord` 재사용
- 저장 정보 화면에서 "다시 녹음"으로 되돌아가면 → 직전에 받아쓴 텍스트는 유지된 채 녹음 화면으로 돌아간다 (처음부터 다시 하지 않음)
- 저장(엔트리 insert) 자체가 실패하면 → 기존과 동일하게 에러 문구 + 재시도, 이 경우는 구조화까지 갈 필요 없이 저장 단계부터 재시도

## 이번에 안 하는 것
(안 적으면 시키지 않은 것까지 만들어 옵니다)

- 파형 막대 개수·간격의 정밀 튜닝, 주파수 대역별 분석(스펙트럼) — 단순 볼륨(RMS/피크) 레벨만 반영
- 경과 시간 카운터(00:42 같은 표시)의 정밀 동기화 — 초 단위 근사치면 충분, 정지 후 재생/되감기 기능 없음
- 진입 화면의 "최근 기록 N건" 카운트 — 실시간 집계 대신 이번엔 생략 (완료 조건에 없음)
- 저장 정보 화면에 태그 직접 선택 UI 추가 — 와이어프레임 "Try next" 제안일 뿐 이번 스코프 아님
- 각 단계에 별도 URL(`/record/voice` 등) 부여 — 아래 "물어볼 것" 결정 전까지는 `RecordPage` 내부 상태(step)로만 전환

## 건드릴 파일
(새로 만들 파일 / 고칠 파일)

- **대폭 수정**: `src/pages/RecordPage.tsx` — 단일 폼을 `step` 상태(`'choice' | 'voice' | 'typing' | 'details'`) 기반 4단계로 재구성
- **수정**: `src/lib/useSpeechInput.ts` — 정지 후에도 마지막 `transcript`를 유지한 채 재시작(이어 녹음) 가능하도록 보완, 에러 발생 시에도 기존 `transcript`를 지우지 않도록 조정
- **신규**: `src/lib/useMicLevel.ts` — `getUserMedia` + Web Audio API `AnalyserNode`로 마이크 입력 볼륨(0~1 정규화 레벨)을 주기적으로 읽어주는 훅. `useSpeechInput`과는 별도 스트림(브라우저가 동시에 두 개의 마이크 스트림 열기를 허용하는지 확인 필요 — 안 되면 하나의 스트림을 공유하도록 조정)
- **신규**: `src/components/VoiceWaveform.tsx` — 레벨 값 배열을 받아 막대 그래프로 렌더링
- **재사용 그대로**: `src/lib/recordValidation.ts` (`canSubmitRecord`), `api/structure.ts`, `entries`/`entries_structured`/`entry_tags` 저장 로직 — 데이터 흐름 자체는 안 바꾸고 화면 순서만 재구성

## 확인 방법
(테스트 + 직접 눌러볼 순서)

1. `npm run build` — 타입체크 통과 확인
2. `npm run test` — `recordValidation.test.ts` 등 기존 테스트 계속 통과 확인
3. 마이크 있는 브라우저(Chrome)에서: 진입 화면 → "음성으로 기록" → 몇 마디 말하고 정지 → 전사 텍스트가 저장 정보 화면에 그대로 넘어오는지 확인
3-1. 말하는 중 파형 막대 높이가 실제 목소리 크기에 따라 움직이는지, 조용할 때는 낮게 유지되는지 확인
4. 하단 큰 녹화 버튼을 직접 눌러도 같은 음성 경로로 들어가는지 확인
5. "타이핑으로 기록" → 텍스트 입력 → 저장 정보 화면으로 정상 진입하는지 확인
6. 저장 정보 화면에서 "다시 녹음"을 눌러 뒤로 갔다가 다시 정지했을 때 텍스트가 유지되는지 확인
7. 저장 정보 화면에서 제목/컬렉션 선택 후 "기록 저장하기" → `/entries/:id`로 이동 확인
8. 개발자 도구에서 마이크 권한을 거부한 상태로 진입 → "음성으로 기록" 비활성 + 안내 문구 확인
9. `/api/structure`가 실패하도록 네트워크를 끊고 저장 시도 → "다시 시도" / "구조화 없이 저장만 하고 나가기" 둘 다 동작 확인
