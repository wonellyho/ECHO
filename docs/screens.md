# 화면 설계 — 엔드포인트 기반 정리

현재 배포된 API 엔드포인트(`POST /api/structure`, `POST /api/star`, `POST /api/insights`) 기준으로,
이 엔드포인트들이 실제로 쓰이는 사용자 플로우를 먼저 쓰고, 거기서 필요한 화면을 뽑아 정리한다.

## 1. 플로우 3개

**플로우 1 — 신규 사용자가 오늘 있었던 일을 기록해두려고**
로그인 화면 → 기록 화면(`/`) → (저장 시 자동 구조화) → 기록 상세 화면(`/entries/:id`)

**플로우 2 — 면접을 앞둔 사용자가 "갈등 해결" 경험을 찾아 STAR로 정리하려고**
로그인 화면 → 내 경험 목록 화면(`/entries`, 태그 필터로 갈등만 보기) → 기록 상세 화면(`/entries/:id`, STAR로 변환 클릭)

**플로우 3 — 의욕이 떨어진 사용자가 자신의 에너지원/소진요인을 돌아보려고**
로그인 화면 → 패턴 화면(`/insights`, 다시 분석하기 클릭) → 결과 확인 → (근거가 궁금해서) 근거 기록의 상세 화면(`/entries/:id`, 패턴 탭)

## 2. 필요한 화면 목록

위 3개 플로우에서 나온 화면은 다음 5개다 (전부 이미 구현·배포되어 있음):

- 로그인 화면 (LoginPage)
- 기록 화면 (RecordPage)
- 내 경험 목록 화면 (EntriesPage)
- 기록 상세 화면 (EntryDetailPage)
- 패턴 화면 (InsightsPage)

## 3. 화면 표

| 화면 이름 | 사용자가 하는 일 | 부르는 엔드포인트 | 빈 상태 | 에러 상태 |
|---|---|---|---|---|
| 로그인 화면 | 이메일/비밀번호로 로그인 | 없음 (Supabase Auth 직접 호출) | 해당 없음 | 로그인 실패 시 에러 문구 표시 |
| 기록 화면 | 텍스트/음성으로 경험을 남기고 저장 | `POST /api/structure` | 해당 없음 (입력 폼) | 저장 실패/구조화 실패 시 에러 문구, 재시도 가능 |
| 내 경험 목록 화면 | 태그+키워드로 기록을 필터링해 찾고, 하나를 골라 상세로 이동 | 없음 (Supabase 직접 조회) | "기록이 없습니다" 문구 | 별도 처리 없음 — 조회 실패 시 안내 없이 빈 목록처럼 보임 |
| 기록 상세 화면 | 구조화 결과 확인/수정, STAR로 변환, 관련 패턴(근거) 확인 | `POST /api/star` (STAR 변환 시에만; 조회/수정은 Supabase 직접) | 구조화 결과 없으면 "불러오는 중" 문구, 패턴 탭은 "관련 패턴 없음" 안내 | STAR 변환 실패·수정 저장 실패 시 각각 에러 문구, 재시도 가능 |
| 패턴 화면 | 전체 기록 기반 에너지원/소진요인 재분석 실행 및 확인 | `POST /api/insights` | 기록 3개 미만이면 "N개 이상 쌓이면 분석" 안내 | 재생성 실패 시 에러 문구, 재시도 가능 |

## A. 어느 화면에도 안 붙는 엔드포인트

**없음.** 배포된 엔드포인트 3개(`/api/structure`, `/api/star`, `/api/insights`) 전부 위 표의 화면에서 실제로 호출된다.

## B. 화면에 필요한데 엔드포인트가 없는 것

**내 경험 목록 화면의 "질문 기반 검색"** — PRD(`PRD_ECHO.md` §6-4 "질문이나 태그로 과거 경험 검색")가 요구하는 건 "갈등을 해결한 경험" 같은 자연어 질문 검색인데, 지금은 태그 선택 + 단순 키워드 포함 검색(`filterEntries`, 클라이언트에서 `raw_text`에 문자열 포함 여부만 확인)만 있고, 이를 위한 서버 엔드포인트는 없다. 자연어 질문을 구조화 데이터와 매칭하려면 별도 검색/임베딩 엔드포인트가 필요할 것으로 보이며, 현재는 존재하지 않는다.
