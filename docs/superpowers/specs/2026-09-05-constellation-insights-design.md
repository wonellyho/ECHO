# 패턴 탭 — 경험 별자리 (3D 성좌 시각화)

패턴 탭을 텍스트 리스트에서 **3D 별자리 우주**로 바꾼다. 경험 하나가 별 하나이고,
공통 태그로 별끼리 선이 이어지며, 에너지원/소진 인사이트의 근거 기록들이 각각 별무리를 이룬다.

레퍼런스: CodePen "Particle Constellation V3.0" — 3D 공간에 흩어진 점 + 가까운 점끼리 연결선.

기존 `InsightsPage`의 텍스트 인사이트 리스트는 사라지지 않고 **군집 라벨을 탭하면 뜨는
오버레이 카드**로 옮겨간다.

---

# 기능 1: 사용자가 자기 경험을 3D 별자리로 본다

## 완료 조건
- [ ] 패턴 탭에 들어가면 어두운 우주 배경에 내 경험들이 별로 떠 있다
- [ ] 별무리가 세 덩어리로 나뉘어 보인다 — 전체 경험(위 중앙), 에너지원(좌하), 소진(우하)
- [ ] 에너지원 별은 따뜻한 색, 소진 별은 차가운 색, 나머지는 중립 흰색으로 구분된다
- [ ] 각 군집 옆에 이름 라벨이 떠 있다
- [ ] 공통 태그가 있는 별끼리 가는 선으로 이어져 있다
- [ ] 같은 컬렉션의 별끼리는 더 밝고 굵은 선으로 이어진다
- [ ] 손가락으로 드래그하면 우주가 회전하고, 핀치하면 확대/축소된다
- [ ] 가만히 두면 아주 천천히 자동으로 돈다
- [ ] 새로고침해도 같은 별이 같은 자리에 있다

## 안 되는 경우
- 기록이 하나도 없을 때 → 우주 대신 "첫 기록을 남기면 첫 별이 뜹니다" 안내와 기록 탭 링크
- 기록은 있는데 `insights`가 비어 있을 때 → 별이 전부 중립 성운 하나로만 뜨고,
  하단에 "패턴 분석하기" 버튼. 분석이 끝나면 별들이 세 군집으로 갈라진다
- 기록이 3개 미만일 때 → 지금처럼 "기록이 3개 이상 쌓이면 패턴을 분석해드려요 (현재 N개)" 문구 유지
- 한 경험이 energizer와 drainer 양쪽 근거일 때 → **에너지원 군집에만** 별 하나로 둔다 (아래 결정 사항)
- 태그가 하나도 없는 경험 → 별은 뜨지만 연결선이 없는 외딴 별이 된다 (정상 동작)
- 데이터를 못 불러왔을 때 → 우주를 그리지 않고 에러 문구 + 다시 시도 버튼
- `prefers-reduced-motion`이 켜진 기기 → 자동 회전과 카메라 트윈을 끄고 즉시 전환
- 탭이 백그라운드로 가면 → `requestAnimationFrame` 루프를 멈춘다 (모바일 배터리)
- WebGL 컨텍스트를 못 만드는 기기 → 우주 대신 `ClusterSummaryCard` 두 장(에너지원/소진)을
  세로로 펼친 정적 화면으로 폴백한다 (같은 컴포넌트를 재사용하므로 리스트 코드를 따로 남기지 않는다)

## 이번에 안 하는 것
- LLM 임베딩 기반 의미 유사도 (태그·컬렉션만 사용)
- 시간축 애니메이션 (기록 순서대로 별이 하나씩 켜지는 연출)
- 별자리 이미지 저장/공유 (PRD §6이 SNS/공유를 스코프에서 제외)
- 군집 이름을 사용자가 직접 바꾸기
- 별 위치를 사용자가 끌어서 옮기기

# 기능 2: 사용자가 별을 눌러 그 경험의 상세를 본다

## 완료 조건
- [ ] 별을 탭하면 카메라가 그 별로 부드럽게 다가가며 별이 커진다
- [ ] 확대된 별 위로 경험 상세 카드가 뜬다 (상황 / 행동 / 결과 / 감정 + 태그)
- [ ] 카드에 "자세히 보기"가 있고, 누르면 기존 경험 상세 페이지로 간다
- [ ] 카드를 닫거나 빈 공간을 탭하면 원래 시야로 돌아간다
- [ ] 카드가 떠 있는 동안에도 우주는 뒤에서 계속 보인다

## 안 되는 경우
- 구조화가 안 끝난 기록(`status !== 'done'`) → 카드에 원문 앞부분만 보이고
  "아직 정리 중이에요" 문구가 뜬다
- 별이 서로 겹쳐 보일 때 → 카메라에 가장 가까운 별 하나만 선택된다
- 카드가 열린 채로 드래그하면 → 카드가 닫히지 않고 회전도 잠긴다 (오작동 방지)
- 태그가 없는 경험 → 태그 줄을 통째로 숨긴다 (빈 자리를 남기지 않는다)

## 이번에 안 하는 것
- 카드 안에서 기록 편집
- 카드에서 STAR 변환 실행 (상세 페이지에 이미 있음)
- 이웃 별로 스와이프 이동

## 건드릴 파일
| 파일 | 신규/수정 | 내용 |
|---|---|---|
| `src/components/constellation/StarDetailCard.tsx` | **신규** | 별 상세 오버레이 카드 |
| `src/components/constellation/ConstellationCanvas.tsx` | 수정 | raycast 선택 + 카메라 포커스 트윈 |
| `src/pages/InsightsPage.tsx` | 수정 | 선택된 entry 상태 관리 |

## 확인 방법
배포 URL 패턴 탭에서 별을 탭 → 카메라가 다가가고 카드가 뜨는지 → "자세히 보기"로
상세 페이지 이동 → 뒤로가기 → 우주가 다시 보이는지. 카드 닫기로 원래 시야 복귀하는지.

# 기능 3: 사용자가 군집을 눌러 그 패턴의 요약을 읽는다

## 완료 조건
- [ ] 에너지원 군집 라벨을 탭하면 energizer 인사이트 요약 문장들이 오버레이 카드로 뜬다
- [ ] 소진 군집 라벨을 탭하면 drainer 인사이트 요약 문장들이 뜬다
- [ ] 각 요약 문장 아래에 근거 기록 개수가 보인다
- [ ] 요약 문장을 탭하면 그 인사이트의 근거 별들만 남기고 나머지가 흐려진다
- [ ] 카드 안에 "다시 분석하기" 버튼이 있고, 지금과 똑같이 인사이트를 재생성한다
- [ ] 재생성이 끝나면 우주가 새 군집 배정으로 다시 그려진다

## 안 되는 경우
- 해당 타입의 인사이트가 하나도 없을 때 → 라벨이 아예 뜨지 않고 그 군집도 비어 있다
- 재생성 중일 때 → 버튼이 비활성화되고 "분석 중..." 표시 (중복 호출 방지)
- 재생성이 실패했을 때 → 에러 문구가 뜨고, **기존 별자리는 그대로 유지된다**
  (지금 코드는 실패 시 목록을 비우는데, 우주가 통째로 사라지면 손실감이 크다)
- 기록이 3개 미만이라 재생성이 막힐 때 → 버튼 대신 안내 문구

## 이번에 안 하는 것
- 인사이트 개별 삭제/수정
- 인사이트 히스토리 (예전 분석 결과 보기)
- 인사이트 생성 API(`/api/insights`) 자체의 변경

기존 별자리가 남아 있는지.

## 결정 사항

### 군집 배정은 `insights.evidence_entry_ids`를 그대로 쓴다

새 API도 새 테이블도 만들지 않는다. `insights` 테이블에 이미 근거 entry id 배열이 있으므로
그것을 뒤집어 `entry_id → cluster` 맵을 만든다.

| 군집 | 대상 | 색 |
|---|---|---|
| `energizer` | `type='energizer'` 인사이트의 근거 | 앰버 계열 (`#F5B451` 근처) |
| `drainer` | `type='drainer'` 인사이트의 근거 | 블루그레이 계열 (`#7C89A8` 근처) |
| `neutral` | 위 어디에도 안 쓰인 나머지 전부 | 화이트 (`#E8EAF2`) |

감정(`entries_structured.emotion`)으로 자동 분류하는 방식을 쓰지 않은 이유: 감정은 자유
텍스트라 분류 규칙을 새로 만들어야 하고, 오분류하면 "기록에 없는 것을 단정하지 않는다"는
PRD §7 근거성 원칙을 정면으로 어긴다. 근거 배열은 이미 LLM이 근거를 대고 만든 값이다.

**양쪽 근거인 경험은 에너지원 우선.** 별을 복제하면 사용자가 "이게 두 번 세어졌나?" 하고
혼란스러워하고, 연결선 개수도 이상해진다. 한 별은 정확히 한 군집에만 속한다.

### 군집 배치와 별 좌표는 결정적으로 계산한다

세 군집 중심은 고정 삼각 구도:

| 군집 | 중심 좌표 |
|---|---|
| `neutral` | `(0, 7, 0)` |
| `energizer` | `(-10, -5, 0)` |
| `drainer` | `(10, -5, 0)` |

각 군집 안에서 별 위치는 **entry id 문자열 해시**로 정한다 — 해시에서 뽑은 세 값을
구면좌표(θ, φ, r)로 바꿔 군집 중심 주위에 흩뿌린다. 반경은 군집 내 별 개수에 따라
`baseRadius * cbrt(count)`로 키워, 별이 많아져도 밀도가 일정하게 유지된다.

`Math.random()`을 쓰지 않는 이유가 핵심이다. 새로고침마다 별이 다른 자리로 가면 "왼쪽 위
저 별이 그때 그 발표 경험" 같은 공간 기억이 성립하지 않는다. PRD §8의 성공 기준에
"회상 가능성"이 있고, 이 화면이 그 기준을 직접 겨냥한다.

### 연결선 규칙

- **같은 군집 안에서만** 잇는다. 군집을 가로지르는 선은 삼각 구도를 뭉개서 세 덩어리로
  보이던 것이 하나의 털뭉치로 무너진다
- 공통 태그 1개 이상 → 선 (`opacity 0.15`, 얇게)
- 같은 컬렉션 → 더 밝고 굵게 (`opacity 0.35`)
- **별 하나당 연결 최대 3개.** 공통 태그 수가 많은 순, 동점이면 entry id 사전순으로 잘라
  결과가 결정적이 되게 한다

3개 제한이 필수인 이유: 태그가 6종뿐이라 제한이 없으면 같은 태그를 가진 별들이 완전그래프를
이루고, 경험 30개만 넘어가도 화면이 선으로 덮인다. 별자리는 "몇 개의 의미 있는 연결"이
보일 때만 별자리로 읽힌다.

간선은 양방향 중복을 없앤 뒤(`min(idA,idB)-max(idA,idB)` 키) 단일 `LineSegments`
지오메트리 하나로 그린다.

### plain three.js를 명령형으로 쓴다 (R3F 없이)

씬이 파티클과 선 중심이라 선언형 래퍼(`@react-three/fiber`)의 이득이 적고, React 19와의
버전 호환 리스크만 늘어난다. `ConstellationCanvas`가 `useEffect` 안에서 renderer/scene을
만들고 cleanup에서 `dispose()`한다. React는 캔버스 바깥(오버레이 카드)만 그린다.

`three`만 추가하고 `OrbitControls`는 예제 애드온에서 가져온다
(`three/examples/jsm/controls/OrbitControls.js` — 트리셰이킹됨).

### 계산과 렌더를 파일로 가른다

`buildGraph.ts`와 `layout.ts`는 three.js를 import하지 않는 순수 함수다. 군집 배정 규칙,
연결선 3개 제한, 해시 좌표의 결정성 — 이것들이 이 기능에서 가장 틀리기 쉬운 부분인데,
WebGL 없이 vitest로 직접 검증할 수 있게 된다.

```
src/lib/constellation/
  buildGraph.ts      entries + tags + insights → {nodes, edges, clusters}
  layout.ts          id 해시 → 결정적 3D 좌표
src/components/constellation/
  ConstellationCanvas.tsx   three.js 씬·카메라·raycast (렌더 전담)
  StarDetailCard.tsx        별 상세 오버레이
  ClusterSummaryCard.tsx    군집 인사이트 오버레이
src/pages/InsightsPage.tsx  데이터 로딩 + 선택 상태 조율
```

### 군집 라벨은 HTML 오버레이로 그린다

군집 이름 세 개는 three.js 스프라이트가 아니라 캔버스 위에 절대배치한 HTML 버튼으로 둔다.
매 프레임 군집 중심의 월드 좌표를 화면 좌표로 투영해 위치만 갱신한다. 이유는 세 가지 —
한글 폰트가 기존 UI와 정확히 같게 렌더되고, 탭 히트박스가 손가락 크기로 충분해지며,
버튼이라 스크린리더가 읽는다. 스프라이트로 만들면 셋 다 직접 해결해야 한다.

개별 별의 라벨은 그리지 않는다 (수십 개가 겹치면 읽을 수 없다). 별 이름은 탭했을 때
상세 카드에서만 보인다.

### 별 라벨 폴백

`entries_structured.situation` → `entries.project_title` → `raw_text` 앞부분 순.
경험 탭 카드가 이미 쓰는 규칙과 같게 맞춘다 (두 화면에서 같은 기록이 다른 이름으로
보이면 안 된다).

### 데이터 로딩

`InsightsPage`가 한 번의 `Promise.all`로 `entries` / `entry_tags` /
`entries_structured` / `collections` / `insights`를 가져온다. `EntriesPage`가 이미 앞의
넷을 같은 방식으로 가져오므로 쿼리 형태를 그대로 따른다.

### 모바일 제스처

캔버스 컨테이너에 `touch-action: none`을 줘서 브라우저 스크롤이 회전 제스처를 가로채지
않게 한다. 하단 네비게이션 높이(`--bottom-nav-total`)만큼은 캔버스 높이에서 빼서,
우주가 nav 뒤로 잘리지 않게 한다.
