# 하단 아이콘 네비게이션 + 내 정보 화면

Figma `ECHO` 파일의 메모(`1:4`)와 카드 레퍼런스 이미지(`1:2`)를 반영해, 상단 텍스트 네비게이션을
하단 아이콘 네비게이션으로 옮기고 `내 정보` 탭을 신설한다.

원문 메모:
> nav바 옵션들이 아래에 배치, 1. 홈화면 기록-(녹화, 타이핑 선택화면) 내경험 패턴 내정보 수정

Figma 메모 4개 항목 중 **네비게이션 하나만** 다룬다. 내 경험 탭의 순환 스택·컬렉션 스와이프·
카드 색상은 별도 슬라이스(C)로 남긴다 (`feature-slicing-approach` 관례).

# 기능 1: 사용자가 화면 아래 아이콘으로 탭을 이동할 수 있다

## 완료 조건
- [ ] 화면 아래에 아이콘 + 라벨 4개(기록/내 경험/패턴/내 정보)가 고정으로 보인다
- [ ] 현재 있는 탭의 아이콘과 라벨이 밝게 강조된다
- [ ] 상단에 있던 텍스트 네비게이션 바가 사라졌다
- [ ] 어느 화면에서든 마지막 콘텐츠가 네비게이션에 가리지 않는다
- [ ] 녹화 화면에서 네비게이션이 녹음 버튼을 가리지 않는다

## 안 되는 경우
- 로그인 전에는 → 네비게이션이 아예 렌더되지 않는다 (기존 `user` 가드 그대로)
- 내 경험 탭에서 선택 모드로 하단 바가 뜰 때 → 하단 바가 네비게이션 **위로** 올라가고,
  둘이 겹치지 않는다
- iOS 홈 인디케이터가 있는 기기 → `env(safe-area-inset-bottom)`만큼 아래 여백이 더 붙어
  네비게이션이 인디케이터에 깔리지 않는다

## 이번에 안 하는 것
- 스와이프 제스처로 탭 전환
- 네비게이션 숨김/표시 애니메이션 (스크롤 시 접히기 등)
- 내 경험 탭 자체의 재설계 (순환 스택·컬렉션 스와이프·카드 색상 — 슬라이스 C)

# 기능 2: 사용자가 자기 계정 정보를 보고 닉네임을 바꿀 수 있다

## 완료 조건
- [ ] 내 정보 탭에서 로그인한 이메일이 보인다
- [ ] 닉네임을 입력하고 저장하면 저장됐다는 표시가 뜬다
- [ ] 새로고침해도 저장한 닉네임이 그대로 있다
- [ ] 지금까지 남긴 기록 개수가 보인다
- [ ] 로그아웃 버튼이 여기 있고, 누르면 로그인 화면으로 돌아간다

## 안 되는 경우
- 닉네임이 비어 있거나 공백뿐일 때 → 저장 버튼이 눌리지 않는다
- 저장이 실패했을 때 → 에러 문구가 뜨고 다시 시도할 수 있다
- 기록 개수를 불러오지 못했을 때 → 개수 자리만 비우고 나머지 화면은 정상 동작한다
- 저장 중일 때 → 버튼이 비활성화되어 중복 저장이 안 된다

## 이번에 안 하는 것
- 프로필 사진
- 비밀번호 변경, 이메일 변경
- 계정 삭제
- 알림/테마 설정

## 건드릴 파일
| 파일 | 신규/수정 | 내용 |
|---|---|---|
| `src/pages/ProfilePage.tsx` | **신규** | 내 정보 화면 |
| `src/lib/profileValidation.ts` | **신규** | 닉네임 유효성 (순수 함수) |
| `src/lib/profileValidation.test.ts` | **신규** | 경계값 테스트 |

배포 URL에서 내 정보 탭 → 닉네임 입력 → 저장 → 새로고침 → 값이 남아 있는지.
빈 값/공백만 입력했을 때 저장 버튼이 막히는지. 로그아웃이 동작하는지.

## 결정 사항

### 닉네임 저장 위치 — Supabase Auth의 `user_metadata`

`supabase.auth.updateUser({ data: { nickname } })` 한 번으로 끝난다. 새 테이블도 RLS 정책도
필요 없고, 사용자가 Supabase SQL Editor에서 마이그레이션을 직접 돌릴 필요도 없다.
값이 세션에 이미 들어 있어 별도 조회도 하지 않는다.

`profiles` 테이블을 만드는 관례적 방식을 쓰지 않은 이유: 그 방식의 이점은 "다른 사용자가 내
프로필을 읽을 수 있다"인데, PRD §6이 SNS/공유/랭킹을 명시적으로 스코프에서 제외했으므로
그런 읽기는 앞으로도 생기지 않는다. 프로필 항목이 여러 개로 늘어나면 그때 옮긴다.

### 네비게이션 구성

| 탭 | 경로 | 아이콘 |
|---|---|---|
| 기록 | `/` | 마이크 (`MicIcon`, 녹화 화면 가운데 버튼과 같은 글리프) |
| 내 경험 | `/entries` | 카드 스택 (`CardsIcon`) |
| 패턴 | `/insights` | 물결선 (`PulseIcon`) |
| 내 정보 | `/profile` | 사람 (`UserIcon`) |

- 높이 `4rem` + `env(safe-area-inset-bottom)`
- `bg-slate-950` + `border-t border-slate-800` (다크 테마 팔레트 그대로)
- 활성 `text-slate-50`, 비활성 `text-slate-500`
- 아이콘 아래 `text-[10px]` 라벨 — 레퍼런스 이미지와 동일한 구성
- `aria-current="page"`로 활성 탭을 보조기술에 알린다

`기록` 탭은 `<Link to="/">`를 유지한다. 같은 경로로의 이동이 replace로 처리되며 새
`location.key`를 발급하고, `RecordPage`가 그걸 "첫 화면으로 돌아가라" 신호로 쓴다
(2026-09-01 ambient 슬라이스에서 만든 동작 — 깨뜨리지 말 것).

### 상단 바를 없앤다

각 화면이 이미 자기 제목을 갖고 있어(`내 경험 기록`, 기록 선택 화면의 로고 등) 상단 바가
없어도 맥락이 사라지지 않는다. 로그아웃 버튼은 내 정보 화면으로 옮긴다.

### 레이아웃 충돌 — 이번에 반드시 같이 고쳐야 하는 것

네비게이션이 아래로 내려가면서 기존에 "상단 nav가 있다"는 전제로 짜인 곳들이 깨진다.
빠뜨리면 화면이 실제로 못 쓰게 되므로 완료 조건에 포함한다.

1. **`RecordPage`의 높이 계산 2곳** — `calc(100vh-3.5rem)` / `calc(100dvh-3.5rem)`이
   상단 nav 높이를 빼고 있다. 하단 nav 높이를 빼도록 바꾼다. 특히 녹화 화면은
   `overflow-hidden`으로 화면을 꽉 채우므로, 값이 어긋나면 녹음 정지 버튼이 nav에 깔려
   **녹음을 멈출 수단이 사라진다**.
2. **`EntriesPage`의 선택 모드 하단 바** — `fixed inset-x-0 bottom-0`이라 nav와 정확히
   겹친다. nav 높이만큼 띄운다.
3. **각 화면의 아래 여백** — 스크롤 끝의 콘텐츠가 nav에 가리지 않도록 패딩을 준다.

### 닉네임 유효성 (`profileValidation.ts`)

- 앞뒤 공백을 제거한 뒤 1자 이상이어야 저장 가능 (`canSubmitRecord`와 같은 방식)
- 최대 20자 — 하단 네비게이션이나 목록에서 줄바꿈을 일으키지 않을 길이
- 저장할 때는 앞뒤 공백을 제거한 값을 넣는다
